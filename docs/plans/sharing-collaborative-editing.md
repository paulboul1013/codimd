## 需求與使用流程

在筆記頁首的「發布」與「選單」之間新增「分享」。帳號 A 分享目前筆記的編輯連結，帳號 B 登入後開啟連結，兩人進入同一份筆記，能同時編輯並即時看到彼此的修改。

兩個帳號使用可區分的游標顏色。遠端游標上方持續顯示對方的帳號名稱，不需要移入滑鼠才看得到。

預期使用流程：

1. A 登入並開啟自己擁有的筆記。
2. A 點擊「分享」，看到編輯連結與目前權限。
3. 若目前權限不適合協作，A 點擊「啟用登入者共同編輯」。伺服器確認儲存成功後，畫面顯示已啟用。
4. A 點擊「複製編輯連結」，自行將連結交給 B。
5. B 開啟連結；若尚未登入，完成登入後自動返回相同筆記的編輯頁面。已登入者直接進入。
6. A 與 B 編輯或移動游標時，對方看到即時內容、不同顏色的游標及上方名稱。
7. 重新整理後，兩人仍看到同一份已儲存的正文。
8. A 可在分享視窗明確停止分享；儲存成功後，B 失去讀寫權限，畫面停止同步並顯示權限已被收回。
9. B 若有未確認同步的本機變更，可在撤權提示畫面手動複製或下載；不再寫回原筆記。
10. A 再次啟用共同編輯後，原連結恢復可用。B 重新開啟連結時仍須登入並通過當前權限檢查。

本次只保存設計文件。後續實作、測試與驗收另依本計畫執行。

## 第一版範圍與已確認規則

依使用者 Q1 的選擇，第一版採用「已登入者持連結可共同編輯」，規劃使用既有 `limited` 權限。

`limited` 允許所有已登入且取得網址的人查看與編輯。分享視窗須直接顯示「所有已登入且取得連結的人都能查看及編輯」。連結轉傳給第三個帳號後，第三個帳號登入也能加入。指定成員授權方案已在 Q1 排除。

第一版涵蓋：

- 桌面「發布 → 分享 → 選單」的入口，以及手機選單中的分享入口。
- 顯示、選取與複製同一份筆記的編輯網址。
- 未登入者經登入後自動返回原分享筆記。
- 允許註冊的部署中，保留原筆記目的地，讓新使用者註冊及登入後返回。
- 擁有者明確啟用時切換為 `limited`；明確停止分享時切換為 `private`。
- 雙帳號同步編輯、不同顏色與持續可見的遠端名稱標籤。
- 權限儲存失敗、複製失敗、重連與離線的使用者提示。
- 在線但暫停操作的遠端游標淡化顯示，同名帳號加上短識別碼。
- 停止分享立即撤權，提供本機未確認同步變更的手動救回選項；重新啟用後恢復舊連結。

第一版不加入帳號搜尋、電子郵件邀請、個別成員角色或邀請通知。依 Q12，編輯連結沿用筆記網址，停止分享靠目前權限拒絕存取，再啟用後舊連結恢復，不新增分享 token 或成員資料表。

## Architect：方案比較與選擇

| 方案 | 狀態與權限由誰管理 | 優點 | 代價與判斷 |
| --- | --- | --- | --- |
| A：編輯連結加既有 `limited` | `Note.permission` 與現有 realtime 共同管理 | 重用同步、讀寫權限及房間，不新增資料表 | 無法限制到指定受邀帳號。第一版採用 |
| B：每份筆記的成員授權 | 新增筆記成員資料，統一供 HTTP 與 Socket 授權使用 | 可指定 B、撤銷 B，保留其他帳號無權存取 | 需要 migration、成員管理與所有存取路徑檢查，Q1 已選擇 A |

選 A 的原因是現有程式已具備核心協作能力，本次主要缺分享入口、可確認的權限操作與符合需求的游標呈現。若指定帳號授權成為必要條件，A 就不適用，不能只靠隱藏按鈕達成。

### 使用介面

分享視窗顯示「共同編輯」、唯讀網址欄位、目前存取範圍及「複製編輯連結」。網址使用既有 `noteurl` 加上 `?both`，讓開啟者直接進入編輯與預覽雙欄模式。沿用既有 mode 解析，不帶目前頁面的 hash 或其他查詢參數。

開啟視窗及複製連結都不自動修改權限。擁有者若要切換權限，須另按「啟用登入者共同編輯」，並先看到實際開放範圍。

依 Q6 至 Q8，只有擁有者看到啟用與停止分享操作。「停止分享」明確說明其他帳號將失去查看及編輯權，透過同一個權限儲存確認機制切換 `private`。成功後重新檢查連線並終止其他帳號的同步；伺服器不得再接受其文字操作。失敗時保留已確認的權限狀態，不顯示停止成功。

此設計共用筆記既有權限，發布頁與其他內容入口也必須遵守停止分享後的存取限制。已被他人讀取、複製或下載的內容無法從他人的裝置追回；Q7 保證的是後續存取及協作終止。撤權前已獲伺服器接受的編輯沿用正常儲存流程，撤權後不接受新的未授權寫入。

依 Q12，再次啟用使用同一筆記的同一網址，不建立副本、不輪替網址。重新進入者讀取當前伺服器正文，撤權時留在本機的舊變更不自動重送，以免意外覆寫期間內的新內容。

| 目前狀況 | 分享視窗行為 |
| --- | --- |
| 擁有者，權限為 `limited` | 可直接複製或停止分享，顯示登入者可共同編輯 |
| 擁有者，權限為 `freely` 或 `editable` | 可複製並顯示現有範圍；另提供切換 `limited`，說明會禁止訪客查看 |
| 擁有者，權限為 `private`、`locked` 或 `protected` | 提示目前 B 無法共同編輯，提供啟用按鈕 |
| 非擁有者 | 可複製自己能存取的網址，依現況說明權限，不顯示啟用或停止按鈕 |
| 無擁有者，或部署未允許所需權限 | 顯示現有限制，不提供無法成功的權限操作；啟用前須確認可切換 `limited` 且可用 `private` 停止分享 |
| Socket 未連線 | 可選取網址，權限修改停用並顯示連線狀態 |
| 剪貼簿寫入失敗或不可用 | 保留可選取網址，提示手動複製，不顯示已複製 |

依 Q2，未登入者取得 `limited` 連結時須引導登入，成功後自動返回同份筆記，保留其編輯模式與部署子路徑。登入後重新檢查當時的筆記存取權限，不能僅因登入前取得連結就略過授權。

已追查現有路徑為 `showNote → errorForbidden → 首頁 next → setReturnToFromReferer → session.returnTo → 登入成功返回`。需補上分享連結進入時的登入引導，以及登入失敗重試仍保留目的地。返回網址限同站及目前部署範圍，缺少 Referer 時也須可靠處理。

依 Q11，站上所有已啟用登入方式均須保留目的地，不能只完成 email 登入。實作前盤點各登入入口、回呼及失敗路徑，尤其是未使用現有 return-to helper 的路徑。對外部登入供應商，沒有可用測試帳號或測試環境時須如實標示驗證限制，不把單元測試當成實際供應商登入驗收。

登入取消後回到可重試的登入引導，不建立協作連線，也不把取消當作登入成功；重試保留原筆記目標。依 Q13，若部署允許註冊，註冊成功或失敗後均保留原目標，完成既有註冊程序及登入後再返回。此功能不開啟原本禁止的註冊，也不把註冊成功當成登入成功。若登入期間筆記已停止分享，完成登入後顯示無存取權，不能恢復正文讀取或同步。

### 撤權與本機變更救回

依 Q14，撤權處理須先凍結輸入與送出，保留當下尚未確認同步的本機變更，再清除正常編輯與預覽的正文顯示，改呈現「分享已停止」及手動救回操作。不能先直接導向一般 403 頁而丟失本機工作。

建議的救回契約：

- 只使用這個頁面在撤權前已持有的本機資料，提供複製或下載待確認的變更片段或差異檔，不向伺服器重新讀取正文。
- 「待確認」包含已送出但還沒收到確認的修改，以及尚未送出的修改。確認回覆遺失時，修改可能已儲存，介面不得把全部變更宣稱為確定未儲存。
- 救回資料與原筆記的即時同步分開，救回不會發出正文修改、建立筆記、重新加入房間或變更權限的請求。
- 本機變更僅在目前頁面暫存，由使用者主動複製或下載。離開前提示先保存；不為此功能自動持久化整份筆記。
- 沒有待確認變更時，直接顯示分享已停止，不提供空白的救回操作。
- 分享重新啟用後，不自動重送撤權前的操作。使用者確認當前內容後，再自行決定如何使用救回資料。

撤權前已接受的變更仍由正常儲存流程處理；救回選項不延後伺服器撤權，也不提供新的讀寫權限。

### 資料模型與狀態

以下為規劃契約，採 JavaScript 物件與 JSDoc 即可，不引入 TypeScript。

| 概念 | 重要欄位 | 擁有者與規則 |
| --- | --- | --- |
| 分享網址 | `editorUrl` | 前端由既有 `noteurl` 產生，指向目前筆記 |
| 分享視窗狀態 | `closed`、`ready`、`saving`、`error` | 分享 UI 管理，不將畫面狀態存入筆記 |
| 權限修改結果 | 成功 `{ ok: true, permission }`；失敗 `{ ok: false, code }` | 伺服器確認資料庫結果，前端不自行宣告成功 |
| 帳號身分 | `userid`、`name` | session 與 `User.getProfile` 管理，不接受客戶端指定他人姓名 |
| 即時參與者 | `id`、`userid`、`name`、`color`、`cursor`、`idle`，另規劃焦點狀態 | 以 socket `id` 追蹤每條連線，以 `userid` 判斷同一帳號 |
| 遠端游標 | 最後已知 `{ line, ch }` 或尚無座標的 `null`，另有活躍狀態 | 失焦不清掉最後位置；前端以 `data-clientid` 對應 DOM |
| 同名辨識 | 原帳號顯示名稱，加上需要時才附加的短識別碼 | 依帳號身分產生，在同份筆記中足以區分；不修改原帳號資料 |
| 本機待確認變更 | 當前頁面尚未確認已儲存的本機修改，以及可供手動救回的表示 | 前端暫存，與伺服器授權及正文同步分開 |

權限操作的狀態為 `ready → saving → ready`，失敗則為 `saving → error`。儲存期間停用重複操作。關閉視窗不取消已送達伺服器的修改，再開啟時使用已確認的權限狀態。

### 介面與責任分配

規劃重用 `permission` 事件，增加可選的結果確認 callback。舊有權限選單仍可不提供 callback，廣播資料格式保持 `{ permission }`。

- `permissionChangeEventHandler(permission, acknowledge?)`：負責登入、擁有者、可用權限檢查與持久化。拒絕及資料庫失敗都須回覆結果，不能只 log。
- 前端權限操作：等待 callback 確認後更新成功提示。逾時顯示「尚未確認，請重新確認目前權限」，不得推斷變更未發生，也不自動重送。
- `notifyPermissionChanged`：繼續廣播已儲存的權限，重新檢查每條連線的查看權限。分享視窗也訂閱現有更新。
- 停止分享：所有正文存取路徑套用同一筆記的 `private` 語意，不能僅把編輯器設為唯讀。前端先保留本機待確認變更，凍結送出並切換至撤權提示與手動救回介面；伺服器立即中止未授權的讀寫。
- 分享 UI：管理開關、網址、複製、等待與錯誤顯示。將這些邏輯放在規劃新增的 `public/js/lib/share-note.js`，`index.js` 只負責接線與取得目前狀態。
- 游標呈現：沿用 `buildCursor`、`checkCursorTag` 與既有事件處理。需要時抽出小型可測函式，不另建游標服務。

### 顏色與名稱規則

伺服器為同份筆記中不同帳號分配可區分的顏色。第一版先使用經過明暗主題確認的固定色盤，避免純隨機顏色雖不同卻難以辨認。色盤用盡後以額外候選色避開已佔用色，不限制原有多人加入能力。

同帳號開多個分頁時共用帳號顏色，各連線仍有獨立游標。優先重用該帳號已在線的顏色，其次考慮可用的作者歷史色，再從未佔用色挑選。所有來源都須經相同的房間內衝突檢查，不能在分配完成後直接被作者歷史色覆蓋。

依 Q5，協作期間以同份筆記仍有帳號在線為界。伺服器在這段期間保留帳號與顏色的對應，讓離開再加入的帳號取回原色；所有人離開後可重新分配。連線是否離開沿用伺服器既有斷線確認與清理流程，不新增永久帳號色偏好。

本次只調整即時參與者的顏色分配，不改寫既有 `Author.color`，也不變更歷史作者標示的語意。伺服器傳出的 online users 與 OT client 色彩須使用同一個最終值。作者歷史色可作為候選值，仍須服從當次協作的固定色對應與衝突檢查。

名稱標籤規則：

- 遠端游標可見時，名稱持續可見，預設位於游標上方。
- 上方空間不足時移到下方，靠近左右邊界時保持在編輯區內。
- 使用純文字 DOM API 寫入名稱。既有首次建立標籤將 `user.name` 插入 HTML 字串的做法需一併修正。
- 長名稱可截斷並提供完整文字提示，中文名稱須正常顯示。
- 依 Q10，同份筆記出現同名帳號時，在名稱後附加短識別碼，例如 `小明 · 7F2A`。識別碼以帳號為單位，不因同帳號多分頁而產生多個身分；短碼若碰撞須延長，游標與線上清單使用相同標示。
- 本機自己的游標保留原本輸入體驗。本人可從線上清單辨識自己的帳號顏色；對方看到本人的彩色游標與名稱。
- 依 Q9，仍在線但失焦或閒置時，保留淡化的最後位置與名稱。回到編輯時恢復正常強度；尚未送出過座標者不憑空建立游標。
- 失焦、閒置與斷線分開處理。離線者移除游標；權限被收回者不再接收筆記內容、游標或在線成員事件。
- 離線、重連與線上清單重送不得產生重複或殘留標籤。

## Blast radius：安全前提與待驗證項目

| 前提或風險 | 證據程度 | 可能性與影響 | 驗證方式 |
| --- | --- | --- | --- |
| 僅擁有者能切換權限，HTTP 與即時寫入都遵守 `limited` | 已追查原始碼路徑，尚未執行本次測試 | 中，高 | 非擁有者直接送事件、訪客 HTTP、訪客 Socket 及文字寫入測試 |
| 改為 `limited` 會影響訪客讀取，也可能影響同筆記發布頁 | 已讀取權限檢查；發布入口有共用筆記權限 | 高，中 | 修改前顯示範圍，實測發布頁與訪客失去權限後的連線 |
| 結果確認不能破壞原有無 callback 的權限選單 | 設計契約，待實作 | 中，中 | 舊呼叫與新呼叫均測，資料庫失敗不得顯示成功 |
| 顏色修正可能與歷史作者色、同帳號多分頁互相覆蓋 | 已追查 `queueForConnect` 與 `operationCallback` | 中，中 | 既有作者色碰撞、重連、多人及同帳號雙分頁案例 |
| 線上清單重送可能錯誤清掉仍在線的游標 | DOM 屬性不一致有原始碼證據，實際影響待重現 | 中，中 | 持續重送 online users，確認只有離線 client 被移除 |
| 另一人插入文字後，停著不動的遠端游標可能漂移 | 自訂 line/ch 游標與 OT selection 各有路徑，尚未實測 | 中，中 | B 游標不動，A 在其前方插入與刪除，檢查標籤仍附著正確文字位置 |
| 名稱常駐可能遮擋、超出邊界，或顏色在夜間不清楚 | 須由實際版面驗證 | 中，中 | 長名稱、同位置雙游標、頂行、左右邊界、捲動及明暗主題截圖 |
| 私密筆記不因複製連結就被開放 | 規劃由明確操作變更權限 | 中，高 | 開關視窗與複製後核對資料庫 permission 不變 |
| 登入返回不可導向站外，且返回時筆記可能已被停止分享 | 已追查 `errorForbidden`、return-to helper 與 email 登入；目前失敗重試會遺失 next，站內與子路徑限制仍需完整驗證 | 中，高 | 同站與子路徑返回、登入失敗重試、外站返回值拒絕，以及登入期間撤銷存取的測試 |
| 停止分享後更新 API 仍可能寫入私密筆記 | `updateNote` 沒有檢查 permission 或 owner，有原始碼證據 | 高，高 | owner 離開且房間清空後，非 owner 更新 private 應被拒絕，正文與修訂均不變 |
| 撤權後至斷線前仍有內容回補路徑 | `get_operations` 與延遲 doc 沒有重新驗權，有原始碼證據；實際競態未重現 | 中，高 | 控制計時與事件順序，撤權後不再送出正文、operation history 或新房間事件 |
| 無權重連可能清掉 owner 使用中的房間 | `queueForConnect` 拒絕路徑刪除整個 note pool 項目，有原始碼證據；執行影響待重現 | 中，高 | B 撤權後重連，A 仍能編輯、儲存及接收正確房間狀態 |
| 失焦後保留游標需要最後座標，現有 blur 會清為 null | Q9 與既有事件處理存在差異 | 高，中 | 失焦及閒置保留淡化座標，新加入者也能看到，離線仍正確移除 |
| 一般 403 導頁或重連重送可能丟失本機變更，或把撤權前操作套用到後續正文 | Q14 要求救回本機工作，現有 403 導頁與 OT 重連另有既有行為 | 中，高 | 撤權發生於修改尚未確認時仍可匯出；不再送出操作；重啟分享後也不自動重播舊變更 |
| 註冊與失敗重試可能遺失原筆記目的地 | Q13 已納入；既有 email 註冊回純首頁 | 高，中 | 註冊成功、失敗及再次登入保留目的地，禁用註冊的部署仍維持原限制 |

停著不動的游標若在並行編輯後漂移，先建立重現案例，再沿用現有 OT 或 CodeMirror 的位置追蹤修正。避免新增另一套正文同步協議。需要檢查的既有位置為 `public/vendor/ot/editor-client.js` 與 `public/vendor/ot/codemirror-adapter.js`，不預設修改 vendor 檔案。

已由原始碼排除的重建需求：相同筆記房間已支援 OT 正文同步；帳號名稱已有伺服器來源；`limited` 已有儲存與讀寫規則。這些能力應優先整合，雙帳號執行結果仍待驗證。

## 實作順序與每階段完成條件

1. 建立基準。用現有兩個帳號與兩個獨立瀏覽器 context 開啟測試筆記，記錄現有同步、名稱、顏色、重連及游標位置問題。憑證由環境或本機設定提供，不寫入文件、腳本或截圖。
2. 先補行為測試。涵蓋 owner 驗證、權限確認成功與失敗、舊呼叫、衝突色分配、同帳號分頁，以及撤權時的本機變更救回。確認針對待修改行為的測試先失敗。
3. 完成分享入口與視窗。先做到可取得同份筆記網址、顯示實際範圍與複製。確認開啟與複製沒有改變權限。
4. 完成啟用與停止分享的權限結果確認。以明確按鈕切換 `limited` 或 `private`；回報成功前，資料庫與房間權限已生效，失去權限的 socket 已停止接收新內容。涵蓋更新 API、回補、延遲回覆與重連，不只測試按鈕。
5. 串接所有已啟用登入方式的登入與返回原筆記流程，涵蓋註冊、登入失敗、返回目的地限制與返回時再次授權。
6. 完成色彩、上方常駐名稱及游標生命週期。先處理基準重現的問題，再檢查版面與特殊名稱。
7. 完成撤權提示與本機變更救回，驗證停止分享後沒有正文讀寫或舊操作重送；再次分享使用同一連結且重新讀取目前正文。
8. 執行相關回歸、完整檢查與正式前端重建，啟動更新後的服務進行雙帳號驗收。
9. 保存驗收工具、結果與截圖，對照下表逐項記錄通過或未通過，不將建置成功當作功能驗收。

## 驗收矩陣

| 案例 | 通過條件 |
| --- | --- |
| 桌面與手機入口 | 桌面位於發布與選單之間，手機也能開啟同一分享視窗 |
| 分享同一筆記 | A、B 最後對應同一筆記 ID，筆記數未因分享增加 |
| 同時編輯 | A、B 在不同位置及相同段落交錯輸入，兩端正文收斂，重新整理後資料庫正文一致 |
| 雙帳號顏色 | A 與 B 的最終色彩不同且肉眼可區分，兩端線上清單與遠端游標一致 |
| 名稱持續顯示 | 游標活躍時標籤位於上方，超過兩秒仍可見，顯示各自的伺服器帳號名稱 |
| 同名帳號 | 同名者附短識別碼，游標與線上清單一致；短碼碰撞可區分，同帳號多分頁不被當作不同帳號 |
| 在線暫停 | 對方切換視窗或閒置，保留淡化的最後位置與名稱；恢復輸入後正常顯示，離線則移除 |
| 特殊名稱 | 中文、長名稱、含 HTML 字元名稱皆作為文字呈現，沒有 HTML 執行 |
| 修改權限 | 只有 owner 能啟用，資料庫成功才顯示成功，另一端即時收到變更 |
| 停止分享 | 只有 owner 可操作，成功後其他帳號不能透過編輯頁、其他內容入口或 Socket 繼續讀寫；已開啟編輯器顯示撤權提示 |
| 再次分享 | 停止期間原連結拒絕其他帳號存取，重新啟用後原連結可用，仍為同份筆記，不增加筆記數 |
| 撤權時救回變更 | 有待確認本機修改時可複製或下載，不新增伺服器讀寫；沒有修改則不顯示空白救回操作 |
| 確認回覆遺失 | 已送出但未獲確認的修改以「未確認同步」標示，不錯誤宣稱一定未儲存 |
| 撤權後重新加入 | 不自動重送撤權前變更；重新加入以當前正文為準，救回資料由使用者自行處理 |
| 撤權後 API 寫入 | owner 關閉筆記且房間清空後，其他帳號呼叫更新 API 被拒絕，不改變正文或修訂 |
| 撤權後回補與重連 | 不再送出 operation history 或延遲 doc；被撤權者重連被拒，owner 房間仍可正常使用 |
| 僅開啟或複製 | permission 不變，私密筆記不被自動開放 |
| 未登入與非 owner | 訪客無法讀寫 `limited`；非 owner 直接送權限事件仍被拒絕 |
| 登入後返回 | B 未登入時直接開啟分享連結，登入後自動回到同一筆記；目的地包含部署子路徑與編輯模式 |
| 所有啟用登入方式 | 實際啟用的每種登入方式均可返回原筆記，失敗或取消後重試仍保留目標；未完成外部供應商實測者明確標記限制 |
| 註冊後返回 | 允許註冊時，註冊及登入成功後返回原筆記；註冊失敗重試不丟目標，也不改變原本的註冊開放設定 |
| 登入期間權限改變 | B 登入期間若筆記停止分享，返回後依新權限處理，沒有未授權正文或即時連線 |
| 其他已登入者 | 不必建立第三個真實帳號，以授權測試證明 `limited` 並非指定成員模式，UI 清楚說明 |
| 複製與失敗處理 | 成功才顯示已複製，剪貼簿失敗可手動選取網址，資料庫失敗或確認逾時有正確提示 |
| 游標追蹤 | 插入刪除、捲動、換行、模式切換與改變視窗大小後，標籤仍貼齊游標 |
| 重連與離開 | 斷線有狀態提示，重連恢復同份筆記，關閉 B 後 A 不殘留 B 游標 |
| 同帳號多分頁 | 共用帳號顏色，各自連線可清理，關閉一分頁不清掉其他在線游標 |
| 發布與既有權限 | 發布入口仍正常，六種權限的既有語意與部署限制未被繞過 |
| 子路徑與主題 | 分享連結保留部署路徑，明暗主題及窄螢幕可正常操作 |
